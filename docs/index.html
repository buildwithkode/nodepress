NodePress Headless CMS

An enterprise-grade, self-hosted headless content management system. Design flexible schemas, manage multi-environment workflows, upload assets, and consume content through auto-generated REST APIs, GraphQL, and real-time WebSockets.

Installation — Step by Step

Follow these steps in order. Each step takes only a few minutes. NodePress runs locally on your machine or on any server with Node.js 18+ and PostgreSQL (or Docker).

Already have some tools installed?

Run these commands in your terminal to check. If you see a valid version, you can skip that step.

1

Install Node.js

Already installed? Run node -v — if it shows v18 or higher, skip to Step 2.

Node.js is the engine that runs NodePress. Download and install version 18 or newer (LTS recommended).

Download Node.js from nodejs.org

After installing, verify: node -v should print something like v22.0.0

2

Install Git

Already installed? Run git --version — if it shows a version number, skip to Step 3.

Git is used to download the NodePress source code. You only need to install it — no prior git experience required.

Download Git from git-scm.com

On Windows: click Next through all the installer options — defaults are fine.

3

Install PostgreSQL (or Docker)

Have Docker? Skip this step and Step 5 — Docker manages the database for you. Run docker-compose up -d inside your project folder after Step 4.
Already installed? Make sure you remember the password you set for the postgres user — you'll need it in Step 5. Then skip to Step 4.

PostgreSQL is the database where all your content, users, and schemas are stored.

Download PostgreSQL from postgresql.org

⚠ Important during installation:

  • When asked to set a password for the postgres user, write it down — you will need it in Step 5.
  • Leave the port as 5432 (the default).
  • PostgreSQL runs automatically in the background after installation.

5

Connect NodePress to your database

Using Docker? Skip this step. Run docker-compose up -d in your project root — Docker manages the database and credentials automatically.

Open backend/.env in your editor and configure your database connection string:

What is DATABASE_URL?

It's the URI NodePress uses to connect to PostgreSQL: postgres is the username, the portion after : is your password, localhost:5432 is host & port, and nodepress is the database name.

Didn't set a password? If you left the default postgres install without a password:
DATABASE_URL="postgresql://postgres@localhost:5432/nodepress"

Using Supabase or Cloud PostgreSQL?

In Supabase, open Connect and configure both strings in backend/.env:

  • Transaction pooler (port 6543) powers runtime queries on DATABASE_URL.
  • Session pooler (port 5432) is assigned to DIRECT_URL for migrations.
  • Keep ?pgbouncer=true&connection_limit=1 on DATABASE_URL.

8

Create your admin account (First-time Setup)

Open your browser and navigate to http://localhost:5173. If no users exist, you are automatically redirected to the setup wizard.

Fill in your site name, admin email, and a secure password. Once submitted, your root administrator account is created.

NodePress is now fully operational. The setup wizard permanently locks after the initial account is created. You can immediately create content types, invite team members, upload assets, and consume APIs.

Sessions, Auth & Password Reset

NodePress utilizes a dual-tier token architecture designed for high security, seamless session persistence, and robust lockout recovery.

Token / MechanismLifetimeScope & Cookie PolicyBehavior
Access Token (np_token) 7 Days SameSite=Lax, Path=/ Standard JWT bearer token verifying active API requests and Next.js middleware route protection.
Refresh Token (np_refresh) 30 Days HttpOnly, SameSite=Lax, Path=/api/auth Stored in PostgreSQL. Automatically exchanges for a fresh access token without prompting the user. Rotates on each refresh.
Expired Session Guard Instant Check Next.js middleware Middleware inspects JWT expiration (exp). When expired, stale cookies are purged and a clear re-login prompt is rendered with zero redirect bounce loops.

Webhooks & Dead-Letter Queue (DLQ)

Webhooks automatically POST JSON events to external services whenever content or media changes. Signed with HMAC-SHA256 (X-NodePress-Signature).

• Automatic Retries: 3 attempts with exponential backoff (Immediate, +5m, +30m).

• Dead-Letter Queue (DLQ): Failed deliveries are archived in the DLQ with full payload & error headers.

• 1-Click Re-Delivery: Re-dispatch any failed delivery directly from the admin UI or via POST /api/webhooks/deliveries/:id/retry.

Plugin Architecture & UI Manager

NodePress includes an enterprise-grade extension engine with an internal lifecycle hook bus (PluginHookBus) and a visual Admin Management UI (/plugins). Admins can enable/disable plugins live with 0ms downtime and configure custom settings via a slide-out settings drawer.

🛡️ Crash-Proof Sandboxed Security Model

In legacy CMS engines (like WordPress), a single unhandled error or slow database query in a third-party plugin can crash the entire web server or cause a White Screen of Death (WSOD). NodePress is architected to be 100% crash-proof:

  • Layer 1 Capability-Based Permissions: Plugins must declare explicit permissions (e.g. ['entries:read', 'entries:write']). If an unauthorized action is attempted, execution is blocked and logged.
  • Layer 2 Isolated Error Boundaries: Every hook and filter is wrapped in isolated error boundaries. If a plugin throws an uncaught exception, NodePress catches the error, logs the trace, and continues serving requests smoothly without crashing.
  • Layer 4 Hard 5-Second Timeouts: All asynchronous plugin hooks are wrapped with a 5000ms timeout guard (Promise.race). Slow or hanging external HTTP calls will never lock up CMS transactions.
  • 0-Downtime Dynamic Toggling: Any misbehaving plugin can be instantly deactivated live from the /plugins UI with 1 click.

API Authentication & Token Guide

Do you need a token for every API request? No! For public websites and visitor frontends (Next.js, React, Astro, Vue, mobile apps, or static sites), content reading and form submissions require ZERO authentication tokens. Anyone can query published content without sending headers or secret keys.

The 3-Tier Security Architecture

Tier 1: Public Read APIs No Auth Required (Zero Token)

Used by consumer frontends to render articles, product catalogs, pages, brand settings, sitemaps, and accept contact form submissions.

GET /api/:contentType e.g. /api/posts, /api/products
GET /api/:contentType/:slug e.g. /api/posts/my-first-post
GET /api/brand Public logo, company name, theme colors
POST /api/submit/:formSlug Public forms protected by honeypot & spam shield
GET /api/sitemap.xml Auto-generated dynamic XML sitemap
Tier 2: Headless Frontends & SSG X-API-Key: np_live_...

For static site generation (Astro, Next.js SSG build step), CI/CD content sync pipelines, or external microservices that need scoped access or draft preview without managing user credentials.

Header: X-API-Key: np_live_...
Generate scoped API keys in Admin Panel → Settings → API Keys
Tier 3: Admin & Content Mutations Authorization: Bearer <JWT>

Required for creating, updating, deleting entries, uploading media assets, configuring webhooks, and inviting users. Authenticated via JWT obtained from login.

Header: Authorization: Bearer eyJhbGciOi...
NodePress admin UI rotates access tokens automatically via HttpOnly refresh cookie
